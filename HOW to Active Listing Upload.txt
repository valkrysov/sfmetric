A few specifics on why each piece is what it is:

dbname — Supabase's default database is literally named postgres, not a custom name like your local sfmetric was.
user — must be postgres.<project_ref> (your project ref is vjolxevvleyagviewnnr), not plain postgres. This is the exact issue that caused the "password authentication failed for user postgres" error you hit earlier when we debugged the Streamlit-to-Supabase connection — same fix applies here.
host — aws-0-us-west-1.pooler.supabase.com, matching the region your project is already on.
port: 5432 — this is the Session pooler, not the Transaction pooler (6543). This matters specifically for this script: it runs TRUNCATE, COPY, and multi-statement INSERT ... ON CONFLICT inside real transactions. The Transaction pooler is optimized for many short-lived stateless queries (which is what your deployed Streamlit app uses) and can behave unreliably with this kind of multi-step transactional batch load. The Session pooler behaves like a normal persistent connection, which is what this ETL script needs.
sslmode: "require" — Supabase requires SSL; your local Postgres likely didn't enforce it, so this wasn't needed before.

Get the exact password from Supabase Dashboard → Project Settings → Database → Connection string (or reset it there if you don't have it saved).

Before running: confirm two things exist on Supabase

This script depends on properties_staging and active_listings_staging tables existing (it truncates and copies into them). Since your historical-sales ETL already runs successfully against Supabase, these staging tables were very likely already created during that migration — but worth a quick check in the Supabase SQL editor:

sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_name IN ('properties_staging', 'active_listings_staging', 'sf_neighborhoods');

If all three come back, you're good to run the script unchanged. If any are missing, let me know which, and I'll give you the exact CREATE TABLE statement to match your existing properties/active_listings schema.
